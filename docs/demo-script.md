# Демо-сценарий сквозного пользовательского пути

Рассчитан на видео ~4 минуты или живую демонстрацию. Перед записью: `SEED_DEMO=1 docker compose up --build` — поднимет стек с демо-данными (100 кандидатов, 20 вакансий, приглашения и отклики во всех статусах).

Аккаунты (пароль `demo-password`): `demo-employer@example.com` — работодатель, `demo.candidate.001@example.com` — кандидат с приглашением. Для сегмента регистрации заведите новый email.

## 0. Сетап (0:00–0:15)

Экран: `http://localhost:3000`. Показать страницу входа: ценность платформы слева, форма справа.

Реплика: «syntax — платформа обратного найма. Работодатель находит кандидата по структурированным сигналам тестирования и профиля, а не только по резюме. Зарплата видна до первого контакта».

## 1. Регистрация кандидата (0:15–0:45)

Перейти «Регистрация» → «Я кандидат» → ввести email/пароль → сабмит. Показать блок с ссылкой подтверждения (dev-режим) → перейти по ней → «Email подтверждён» → вернуться ко входу → залогиниться.

Реплика: «Регистрация с подтверждением email и обязательным согласием 152-ФЗ. Контакты по умолчанию скрыты. Реальный PVN-провайдер в демо не подключён».

## 2. Опрос, профиль и тестирование (0:45–2:00)

Кабинет кандидата → «Профиль»: заполнить ФИО, специализацию backend, стек, стаж → «Сохранить». Справа показать анонимную карточку `#ID` без имени.

Реплика: «Слева — полные данные, которые видит только кандидат. Справа — то, что видит работодатель: анонимная карточка».

Перейти «Тестирование» → выбрать Junior → «Начать тестирование» → пройти сессию (по одной задаче, показать прогресс-бар; для демо можно сократить длину через `TASKS_PER_SESSION`) → экран результата.

Реплика: «Механика тестирования: ожидаемая сложность задаётся параметрами 72 концептов банка, а формулировка может быть уникализирована под кандидата — LLM, fallback-пул из 240 задач или детерминированная генерация по seed. По результату — рекомендация по грейду: не понижается принудительно, смена не чаще раза в 3 месяца».

## 3. Работодатель: потребность и подборка (2:00–3:00)

Выйти → залогиниться `demo-employer@example.com`. Показать «Подбор»: категории (специализация × грейд, счётчики кандидатов), активная категория — анонимные карточки.

Реплика: «Механика подбора: работодатель выбирает категорию, а не ищет только по резюме. Внутри — анонимные карточки, и главное правило — подтверждённый профиль всегда выше заявленного: кандидат с пройденным тестом не может проиграть тому, кто только описал стек. Соответствие потребности — аддитивная надбавка к оценке, а не множитель, поэтому самоописанный стек не перевешивает результат теста. В scoring: тесты 40%, достижения ПВН 30%, полнота профиля 10%; кандидат без истории ПВН — корректная перенормировка и явная пометка».

Показать на карточке бейдж «Подтверждён тестом» / «Не подтверждён тестом» и блок «Почему в выдаче» (совпадение стека, близость опыта, результат теста, полнота профиля). Показать, что карточка без теста стоит ниже подтверждённой.

Реплика: «Подтверждение идёт не отдельным экзаменом на каждый навык — двадцать вопросов на стек без реальных данных не откалибровать. Оно выводится из той же единой сессии: если в ней были верные ответы по концептам домена, соответствующие навыки помечаются как проверенные. Дёшево, честно и защитимо».

Показать фильтры «Город» и «Формат работы» → нажать «Подробный профиль» на карточке → анонимная анкета: стек с бейджами «Проверен тестом» / «Заявлен», опыт, грейд, город, формат, достижения ФСП укрупнённо (тип и уровень, без названий и дат). Реплика: «Работодатель видит весь профиль, но не личность: ни ФИО, ни контактов, ни аватара. Достижения намеренно укрупнены — детали соревнования в узкой нише де-анонимизировали бы человека. Личность раскрывается только при взаимном согласии».

Показать фильтр: ввести стек `python` → «Добавить стек» — подборка уточняется, не сбрасываясь. Показать разбор скоринга в карточке (полосы по компонентам с весами).

## 4. Приглашение и раскрытие контактов (3:00–3:40)

На карточке → «Отправить приглашение»: заполнить сообщение, вилку 200 000 – 260 000 ₽, компанию, контакт → отправить.

Реплика: «Зарплатная вилка обязательна — платформа не пропустит приглашение без неё. Контакты кандидата скрыты до принятия».

Выйти → залогиниться кандидатом (например `demo.candidate.001@example.com`, если приглашение отправили ему; иначе тем, кому отправили) → «Приглашения»: показать входящее с условиями и вилкой → «Принять» → контакты раскрыты.

Реплика: «Кандидат видит условия до начала общения. После принятия контакты видны обеим сторонам».

## 5. Классический сценарий: вакансия и отклик (3:40–4:15)

Работодателем → «Вакансии» → «Опубликовать вакансию»: title, специализация, грейд, стек, вилка, описание → создать. Показать редактирование.

Кандидатом → «Вакансии»: выбрать свежую → «Откликнуться» с сообщением → статус отклика в списке «Мои отклики».

Реплика: «Дополнительный сценарий: вакансии и отклики — кандидат без приглашений не теряет инициативу. Работодатель управляет статусами откликов».

## 6. Задания к вакансии (4:15–4:30)

Работодателем → «Задания» → выбрать вакансию → добавить задание вручную (формулировка, варианты, правильный ответ). Кандидатом → откликнуться на вакансию → в модальном окне «Пройти задания» → пройти под прокторингом.

Реплика: «Задания привязаны к вакансии и открываются кандидату после отклика. Проходят под тем же прокторингом, что тестирование: полноэкранный режим, без переключения вкладок. Одна попытка, результат виден работодателю в отклике и не размывает общий балл».

## 7. Финал (4:30–4:45)

Реплика: «Последний прогон содержит backend-тесты; отдельно 10 PostgreSQL/pgvector тестов прошли на Docker-стенде с откатом временных данных. Метрики качества валидации синтетические и не являются рыночной accuracy. Реальные PVN и ATS не настроены. Деплой — docker compose с Alembic до запуска API. Документация и API — в репозитории».

## Запись видео

- Разрешение 1920×1080, курсор подсвечен
- Паузы на ввод данных вырезать
- Запасной вариант по ТЗ: если нет развёрнутого стенда, приложить это видео и `docs/07-deploy.md` к сдаче
